# Оптимизация системного промпта

## 📊 Текущее состояние

### Проблемы

1. **Огромный базовый промпт** (~400+ строк, ~1000+ токенов)
   - Отправляется при каждом запросе
   - Содержит много повторяющейся информации
   - Few-shot примеры занимают ~60% промпта

2. **Отсутствие кэширования**
   - `compose_system_instruction()` вызывается 4+ раза на запрос
   - Базовый промпт читается из `settings` каждый раз
   - Нет мемоизации результатов

3. **Дублирование информации**
   - Правила форматирования повторяются в разных секциях
   - Few-shot примеры слишком подробные
   - Математические правила дублируются

4. **Линейное увеличение при ролях**
   - Базовый промпт + роль = еще больше токенов
   - Нет оптимизации для разных типов запросов

## 🎯 Предложения по оптимизации

### 1. Кэширование промптов (Критично)

**Проблема:** Промпт формируется заново при каждом вызове

**Решение:** Добавить мемоизацию в `compose_system_instruction()`

```python
from functools import lru_cache

# Кэш для базового промпта
_base_prompt_cache = None

def compose_system_instruction(role_prompt: Optional[str]) -> str:
    """Собирает системную инструкцию с кэшированием."""
    global _base_prompt_cache
    
    # Кэшируем базовый промпт (он не меняется)
    if _base_prompt_cache is None:
        _base_prompt_cache = settings.DEFAULT_SYSTEM_PROMPT.strip()
    
    if role_prompt:
        # Кэшируем комбинации базовый + роль
        cache_key = f"{_base_prompt_cache}|||{role_prompt.strip()}"
        if not hasattr(compose_system_instruction, '_cache'):
            compose_system_instruction._cache = {}
        
        if cache_key not in compose_system_instruction._cache:
            compose_system_instruction._cache[cache_key] = (
                _base_prompt_cache + "\n\n# ДОПОЛНИТЕЛЬНАЯ РОЛЬ\n" + role_prompt.strip()
            )
        return compose_system_instruction._cache[cache_key]
    
    return _base_prompt_cache
```

**Экономия:** ~80% времени на формирование промпта

### 2. Сжатие базового промпта (Высокий приоритет)

**Проблема:** Базовый промпт слишком длинный

**Решение:** Создать компактную версию с сохранением функциональности

```python
# Компактная версия базового промпта
COMPACT_SYSTEM_PROMPT = """# РОЛЬ
ИИ-ассистент для Telegram. Отвечай точно, структурированно, используя MarkdownV2.

# ФОРМАТИРОВАНИЕ
✅ Разрешено: `*жирный*`, `_курсив_`, `` `код` ``, `[ссылка](URL)`, `- списки`
❌ Запрещено: HTML теги, `**текст**`, LaTeX `$...$`, неэкранированные спецсимволы

# МАТЕМАТИКА
Формат: `2 × 3 = 6`, `√2`, `1/2`, `x² + 2x + 1 = 0` (НЕ `$...$`)

# СТРУКТУРА ОТВЕТА
1. *Краткое определение* - основное
2. _Детали_ - дополнительные сведения  
3. - Список ключевых элементов
4. [Ссылки](URL) - если есть

# ЭКРАНИРОВАНИЕ
Символы `.`, `!`, `-`, `[`, `]`, `(`, `)`, `*`, `_`, `` ` ``, `~`, `>`, `#`, `+`, `=`, `|`, `{`, `}` → экранировать: `\.`, `\!`, `\-`, и т.д.

# СТИЛЬ
Будь полезным, точным, структурируй логично, используй примеры, объясняй простым языком, будь дружелюбным.

# ПРОВЕРКА
- [ ] Ответ на вопрос
- [ ] MarkdownV2 синтаксис
- [ ] Математика без LaTeX
- [ ] Спецсимволы экранированы"""
```

**Экономия:** ~70% токенов (с ~1000 до ~300 токенов)

### 3. Условная загрузка few-shot примеров (Средний приоритет)

**Проблема:** Few-shot примеры всегда включены, даже когда не нужны

**Решение:** Загружать примеры только для сложных запросов

```python
def compose_system_instruction(role_prompt: Optional[str], include_examples: bool = False) -> str:
    """Собирает системную инструкцию с опциональными примерами."""
    base = _get_base_prompt(include_examples=include_examples)
    if role_prompt:
        return base + "\n\n# ДОПОЛНИТЕЛЬНАЯ РОЛЬ\n" + role_prompt.strip()
    return base

def _get_base_prompt(include_examples: bool = False) -> str:
    """Получает базовый промпт с или без примеров."""
    if include_examples:
        return settings.DEFAULT_SYSTEM_PROMPT.strip()
    return settings.COMPACT_SYSTEM_PROMPT.strip()
```

**Экономия:** ~40% токенов для простых запросов

### 4. Оптимизация для ролей (Средний приоритет)

**Проблема:** При использовании роли базовый промпт все еще очень длинный

**Решение:** Для ролей использовать более компактный базовый промпт

```python
def compose_system_instruction(role_prompt: Optional[str]) -> str:
    """Собирает системную инструкцию с оптимизацией для ролей."""
    # Если есть роль, используем компактную версию базового промпта
    if role_prompt:
        base = settings.COMPACT_SYSTEM_PROMPT.strip()
        return base + "\n\n# ДОПОЛНИТЕЛЬНАЯ РОЛЬ\n" + role_prompt.strip()
    
    # Для обычных запросов используем полную версию
    return settings.DEFAULT_SYSTEM_PROMPT.strip()
```

**Экономия:** ~50% токенов при использовании ролей

### 5. Разделение на модули (Низкий приоритет)

**Проблема:** Весь промпт в одном месте, сложно оптимизировать

**Решение:** Разделить на модули (форматирование, математика, структура)

```python
# app/prompts/modules.py
FORMATTING_RULES = """# ФОРМАТИРОВАНИЕ
✅ `*жирный*`, `_курсив_`, `` `код` ``, `[ссылка](URL)`, `- списки`
❌ HTML, `**текст**`, LaTeX `$...$`"""

MATH_RULES = """# МАТЕМАТИКА
`2 × 3 = 6`, `√2`, `1/2`, `x² + 2x + 1 = 0` (НЕ `$...$`)"""

def build_compact_prompt(modules: list[str]) -> str:
    """Собирает промпт из модулей."""
    return "\n\n".join(modules)
```

**Преимущества:** Легче поддерживать и оптимизировать

- С ролью: ~1200+ токенов
- Время формирования: ~5-10ms на запрос
- Вызовов `compose_system_instruction()`: 4+ на запрос

### После оптимизации:

- С ролью: ~500 токенов (экономия 58%)
- Время формирования: ~0.5-1ms (экономия 80-90%)
- Вызовов с кэшем: 1 реальный, остальные из кэша

### Общая экономия:
- **Токены:** ~50-70% экономии на каждом запросе
- **Время:** ~80-90% экономии на формирование промпта
- **API стоимость:** Прямая экономия от меньшего количества токенов

## 🚀 План внедрения

### Этап 1: Кэширование (Быстро, низкий риск)
1. Добавить мемоизацию в `compose_system_instruction()`
2. Протестировать на всех типах запросов
3. Измерить улучшение производительности

### Этап 2: Компактный промпт (Средний риск)
1. Создать `COMPACT_SYSTEM_PROMPT` в `config.py`
2. Добавить флаг для выбора версии
3. A/B тестирование: сравнить качество ответов
4. Если качество не ухудшилось, использовать компактную версию

### Этап 3: Условная загрузка примеров (Средний риск)
1. Добавить параметр `include_examples` в `compose_system_instruction()`
2. Определить критерии для включения примеров
3. Протестировать на разных типах запросов

### Этап 4: Оптимизация для ролей (Низкий риск)
1. Использовать компактный промпт для ролей
2. Протестировать качество ответов с ролями
3. Если качество не ухудшилось, применить оптимизацию

## ⚠️ Риски и митигация

### Риск 1: Ухудшение качества ответов
**Митигация:** A/B тестирование, постепенное внедрение, возможность отката

### Риск 2: Проблемы с кэшем
**Митигация:** Очистка кэша при изменении настроек, ограничение размера кэша

### Риск 3: Несовместимость с существующими ролями
**Митигация:** Сохранение обратной совместимости, миграция существующих ролей

## 📝 Рекомендации

1. **Начать с кэширования** - быстрая победа, низкий риск
2. **Создать компактный промпт** - значительная экономия токенов
3. **Тестировать качество** - убедиться, что оптимизация не ухудшает ответы
4. **Мониторить метрики** - отслеживать экономию токенов и времени
5. **Постепенное внедрение** - не делать все изменения сразу
