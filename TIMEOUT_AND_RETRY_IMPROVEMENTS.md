# Улучшения timeout и обработки ошибок

## Выполненные изменения

### 1. Увеличение timeout для API запросов

**Проблема:** Некоторые модели имеют низкую пропускную способность, что приводит к таймаутам даже при успешных запросах.

**Решение:** Увеличен timeout с 60 до 120 секунд для обоих API (Gemini и OpenRouter).

**Изменения:**
- `app/services.py` - timeout увеличен до 120 секунд в `_execute_gemini_request` и `_execute_openrouter_request`
- Добавлен комментарий, объясняющий причину увеличения timeout

**Баланс:**
- 120 секунд достаточно для медленных моделей
- Не слишком длинный для ошибочных запросов (2 минуты - разумный предел)

### 2. Добавлена функция определения ошибок

**Новые функции в `app/errors.py`:**

```python
def is_error_message(text: str) -> bool:
    """Определяет, является ли сообщение ошибкой по наличию эмодзи ошибок."""
    error_indicators = ["⏰", "❌", "🔄", "🚫", "⏱️", "💳"]
    return any(text.startswith(indicator) for indicator in error_indicators)

def is_retryable_error(text: str) -> bool:
    """Определяет, можно ли повторить запрос при этой ошибке."""
    # Временные ошибки, которые можно повторить
    retryable_patterns = [
        "⏰",  # Таймаут
        "🔄",  # Перегрузка сервера
        "⏱️",  # Rate limit
        "Превышено время ожидания",
        "перегружен",
        "rate limit",
        "503",
        "unavailable",
        "overloaded"
    ]
```

### 3. Добавлена кнопка "Повторить запрос" для временных ошибок

**Где добавлено:**
- `_handle_regular_chat` - обычный чат
- `_handle_qna_search` - быстрые ответы
- `_handle_research_agent` - глубокий анализ (синтез ответа и выбор URL)
- `_handle_document_question` - вопросы по документам

**Логика:**
- Если ответ является ошибкой (`is_error_message()`), проверяется, можно ли повторить (`is_retryable_error()`)
- Для временных ошибок показывается кнопка "🔁 Попробовать ещё раз" через `build_retry_and_roles_keyboard()`
- Для постоянных ошибок (quota, invalid request) показывается только кнопка выбора роли
- Ошибки не добавляются в историю чата

**Обрабатываемые ошибки с кнопкой повтора:**
- ⏰ Таймауты
- 🔄 Перегрузка сервера (503, unavailable, overloaded)
- ⏱️ Rate limit

**Ошибки без кнопки повтора (постоянные):**
- 🚫 Quota exceeded
- ❌ Invalid request
- 💳 Недостаточно средств

### 4. Обновлена обработка пустых ответов

Теперь пустые ответы также показываются с кнопкой повтора через `build_retry_and_roles_keyboard()`.

## Механизм работы

### Определение ошибки

1. Сервисы (`services.py`) возвращают строку с ошибкой или успешный ответ
2. Ошибки всегда начинаются с эмодзи ошибки (⏰, ❌, 🔄, и т.д.)
3. Функция `is_error_message()` проверяет наличие эмодзи ошибки в начале строки

### Повтор запроса

1. Функция `is_retryable_error()` проверяет, является ли ошибка временной
2. Если ошибка временная - показывается кнопка "🔁 Попробовать ещё раз"
3. При нажатии вызывается `retry_last_callback()`, который повторяет последний запрос пользователя

### Обработка в handlers

Пример обработки в `_handle_regular_chat`:

```python
if response_text:
    if is_error_message(response_text):
        # Ошибка - не добавляем в историю
        chat_state.history.pop()
        await db.update_user_chat(user_id, chat_state)
        
        if is_retryable_error(response_text):
            reply_markup = build_retry_and_roles_keyboard()
        else:
            reply_markup = build_roles_keyboard()
        
        await placeholder_message.edit_text(response_text, reply_markup=reply_markup)
    else:
        # Успешный ответ - добавляем в историю
        # ... обычная обработка
```

## Преимущества

1. **Меньше таймаутов** - увеличенный timeout снижает количество ложных таймаутов
2. **Удобство для пользователей** - кнопка повтора позволяет быстро повторить запрос без перепечатывания
3. **Правильная обработка ошибок** - ошибки не попадают в историю чата
4. **Умная логика** - только временные ошибки показывают кнопку повтора

## Тестирование

### Тест 1: Таймаут

1. Использовать медленную модель OpenRouter
2. Сделать запрос, который может занять время
3. Если происходит таймаут, должна появиться кнопка "🔁 Попробовать ещё раз"

### Тест 2: Перегрузка сервера

1. Сделать запрос во время высокой нагрузки
2. Если получаем ошибку 503, должна появиться кнопка повтора

### Тест 3: Постоянная ошибка

1. Попробовать сделать запрос при исчерпанной квоте
2. Кнопка повтора НЕ должна появляться (только кнопка выбора роли)

### Тест 4: Успешный ответ

1. Сделать обычный запрос
2. Ошибки не должно быть, кнопка повтора не должна появляться
3. Ответ должен добавиться в историю
