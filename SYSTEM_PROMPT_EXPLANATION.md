# Объяснение: Как передается системный промпт в API

## 📊 Текущая ситуация

### ✅ Gemini API - Правильно реализовано

Для **Gemini API** системная инструкция передается **отдельно** от истории сообщений:

```python
# app/services.py, строки 196-200
config = types.GenerateContentConfig(
    safety_settings=settings.SAFETY_SETTINGS
)

if system_instruction:
    config.system_instruction = safe_system_instruction  # ← Отдельный параметр!

response = client.models.generate_content(
    model=model_name,
    contents=contents,  # ← История сообщений БЕЗ системного промпта
    config=config       # ← Системная инструкция здесь
)
```

**Преимущества:**
- ✅ Системная инструкция НЕ входит в историю сообщений
- ✅ Не занимает токены в каждом запросе (передается один раз на сессию)
- ✅ Оптимизировано на уровне API

### ⚠️ OpenRouter API - Ограничение стандарта

Для **OpenRouter API** (который использует стандарт OpenAI API) системное сообщение **должно быть** в массиве `messages`:

```python
# app/services.py, строки 606-609
messages.append({
    "role": "system",
    "content": system_content  # ← В массиве messages
})

payload = {
    "model": model_name,
    "messages": messages  # ← Системное сообщение здесь
}
```

**Причина:**
- Это стандарт OpenAI API (который использует OpenRouter)
- Системное сообщение должно быть первым в массиве `messages`
- Нет отдельного параметра для системной инструкции

**Ограничение:**
- Системное сообщение отправляется с каждым запросом
- Занимает токены в каждом запросе

## 🔧 Оптимизация

### Что мы сделали:

1. **Для Gemini API** - уже оптимально (системная инструкция отдельно)

2. **Для OpenRouter API** - добавили оптимизацию:
   - Автоматическое использование компактной версии промпта
   - Экономия ~70% токенов на системном сообщении
   - Код в `app/services.py`, строки 586-604

### Как это работает:

```python
# Если системный промпт содержит роль
if "# ДОПОЛНИТЕЛЬНАЯ РОЛЬ" in system_content:
    # Разделяем базовый промпт и роль
    parts = system_content.split("# ДОПОЛНИТЕЛЬНАЯ РОЛЬ", 1)
    role_prompt = parts[1].strip()
    
    # Используем компактную версию базового промпта
    compact_base = settings.COMPACT_SYSTEM_PROMPT
    system_content = compact_base + "\n\n# ДОПОЛНИТЕЛЬНАЯ РОЛЬ\n" + role_prompt
    # Экономия: ~700 токенов → ~200 токенов
```

## 📈 Результаты

### Gemini API:
- ✅ Системная инструкция передается отдельно
- ✅ Не занимает токены в каждом запросе
- ✅ Оптимально по умолчанию

### OpenRouter API:
- ⚠️ Системное сообщение в массиве (стандарт API)
- ✅ Используется компактная версия промпта
- ✅ Экономия ~70% токенов на системном сообщении

## 🎯 Итог

**Для Gemini API** - мы уже используем правильный подход: системная инструкция передается отдельно через `config.system_instruction`.

**Для OpenRouter API** - ограничение стандарта OpenAI API не позволяет передавать системную инструкцию отдельно, но мы оптимизировали размер системного сообщения, используя компактную версию промпта.
