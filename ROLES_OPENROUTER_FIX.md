# Исправление проблемы с применением ролей в OpenRouter

## Проблема

Роли не применялись при использовании моделей через OpenRouter. Бот сообщал об успешном применении роли, но ответы моделей были стандартными, как будто роль не применялась.

## Причина

Обнаружена критическая ошибка: **двойной вызов функции `compose_system_instruction`**.

### Как это работало (неправильно):

1. **При применении роли** (`app/handlers/callbacks.py`):
   ```python
   chat_state.system_prompt = prompts.compose_system_instruction(role['prompt'])
   ```
   Сохранялся уже готовый системный промпт, который включал:
   - Базовый системный промпт (`settings.DEFAULT_SYSTEM_PROMPT`)
   - + Роль пользователя

2. **При использовании роли** (`app/handlers/agent.py`):
   ```python
   system_instruction = prompts.compose_system_instruction(chat_state.system_prompt)
   ```
   Функция `compose_system_instruction` вызывалась **еще раз**, что приводило к:
   - Добавлению базового промпта еще раз
   - Потере или искажению роли

### Результат:

В итоге системный промпт содержал дублированный базовый промпт и некорректную роль, что приводило к тому, что модели OpenRouter игнорировали роль.

## Решение

Изменена логика сохранения ролей:

1. **При применении роли** - сохраняется **только промпт роли** (без базового):
   ```python
   chat_state.system_prompt = role['prompt']  # Только промпт роли
   ```

2. **При использовании роли** - вызывается `compose_system_instruction` **один раз**:
   ```python
   system_instruction = prompts.compose_system_instruction(chat_state.system_prompt)
   ```

3. **В OpenRouter API** - системный промпт передается правильно:
   ```python
   if system_instruction:
       messages.append({
           "role": "system",
           "content": str(system_instruction).strip()
       })
   ```

## Измененные файлы

### 1. `app/handlers/callbacks.py`

**Изменения:**
- `role_apply_callback()` - теперь сохраняет только промпт роли
- `role_clear_callback()` - исправлено сохранение `None`
- `role_custom_apply_callback()` - теперь сохраняет только промпт роли
- `role_custom_save_callback()` - теперь сохраняет только промпт роли

**До:**
```python
chat_state.system_prompt = prompts.compose_system_instruction(role['prompt'])
```

**После:**
```python
chat_state.system_prompt = role['prompt']  # Только промпт роли
```

### 2. `app/services.py`

**Изменения:**
- Добавлена проверка на пустую строку перед добавлением системного сообщения
- Добавлено логирование для отладки

**Улучшения:**
```python
if system_instruction:
    system_content = str(system_instruction).strip()
    if system_content:
        messages.append({
            "role": "system",
            "content": system_content
        })
        logging.debug(f"Added system instruction to OpenRouter request (length: {len(system_content)})")
```

## Как это работает сейчас

### 1. Применение роли

```python
# Пользователь выбирает роль "📚 Преподаватель"
# Промпт роли: "Ты — Преподаватель. Объясняй по шагам..."

# Сохраняется в БД:
chat_state.system_prompt = "Ты — Преподаватель. Объясняй по шагам..."
```

### 2. Использование роли

```python
# При запросе к AI:
system_instruction = compose_system_instruction(chat_state.system_prompt)
# Результат:
# Базовый промпт + "\n\n# ДОПОЛНИТЕЛЬНАЯ РОЛЬ\n" + "Ты — Преподаватель..."
```

### 3. Передача в OpenRouter

```python
messages = [
    {
        "role": "system",
        "content": "<полный системный промпт с ролью>"
    },
    {
        "role": "user",
        "content": "<вопрос пользователя>"
    }
]
```

## Преимущества нового подхода

1. **Один вызов compose_system_instruction** - роль применяется корректно
2. **Гибкость** - можно изменить базовый промпт без пересохранения всех ролей
3. **Правильная работа с OpenRouter** - системный промпт передается в стандартном формате
4. **Совместимость** - работает одинаково для Gemini и OpenRouter

## Тестирование

### Тест 1: Применение предустановленной роли

1. Выберите модель OpenRouter: `/model` → `gpt-4o`
2. Выберите роль: `/roles` → `📚 Преподаватель`
3. Задайте вопрос: "Объясни что такое Python"
4. **Ожидаемый результат:** Ответ должен быть в стиле преподавателя (пошаговое объяснение, задания, проверка понимания)

### Тест 2: Применение кастомной роли

1. Выберите модель OpenRouter: `/model` → `claude-3.5-sonnet`
2. Создайте роль: `/roles` → "Создать роль" → "Эксперт по кулинарии"
3. Примените сгенерированную роль
4. Задайте вопрос: "Как приготовить пасту?"
5. **Ожидаемый результат:** Ответ должен соответствовать роли эксперта по кулинарии

### Тест 3: Проверка логов

В логах должно быть видно:
```
DEBUG: Added system instruction to OpenRouter request (length: XXXX)
DEBUG: OpenRouter request includes system message (length: XXXX)
DEBUG: Total messages in request: 2
```

## Известные ограничения

1. **Существующие роли в БД** - если роли были применены до исправления, они могут содержать дублированный базовый промпт. Рекомендуется переприменить роли.

2. **Миграция данных** - можно создать скрипт миграции для очистки дублированных промптов, но это не обязательно, так как при переприменении ролей они будут сохранены правильно.

## Дополнительные улучшения

Добавлено логирование для отладки:
- Длина системного промпта
- Количество сообщений в запросе
- Наличие системного сообщения

Это поможет быстро выявить проблемы в будущем.
