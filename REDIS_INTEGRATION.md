# 🔴 Redis Integration Guide

## 📋 Обзор

Gemaibot поддерживает Redis для персистентной очереди задач и кэширования. Это позволяет:
- **Сохранять задачи** при перезапусках бота
- **Масштабировать** на несколько инстансов
- **Использовать** внешние Redis сервисы (Upstash, DigitalOcean, AWS, Azure)

## 🚀 Быстрый старт

### 1. Локальный Redis (для разработки)

```bash
# Ubuntu/Debian
sudo apt update
sudo apt install redis-server
sudo systemctl start redis-server

# macOS
brew install redis
brew services start redis

# Windows
# Скачайте Redis для Windows или используйте WSL
```

### 2. Внешний Redis сервис (рекомендуется для продакшена)

#### **Upstash.com (Бесплатный тариф)**
1. Зарегистрируйтесь на [console.upstash.com](https://console.upstash.com/)
2. Создайте новый Redis database
3. Скопируйте REDIS_URL из консоли
4. Добавьте в переменные окружения:

```env
REDIS_URL=redis://default:password@us1-capable-rat-12345.upstash.io:12345
ENABLE_PERSISTENT_QUEUE=true
```

**Бесплатный тариф Upstash:**
- ✅ 10,000 запросов/день
- ✅ 256MB RAM
- ✅ Глобальное распределение
- ✅ SSL/TLS по умолчанию
- ✅ Веб-интерфейс мониторинга

#### **Другие сервисы**

```env
# DigitalOcean Managed Redis
REDIS_URL=redis://default:password@redis-12345.us-east-1-1.ondigitalocean.com:12345

# Azure Cache for Redis
REDIS_URL=redis://:password@hostname.redis.cache.windows.net:6380

# AWS ElastiCache
REDIS_URL=redis://hostname.cache.amazonaws.com:6379
```

## ⚙️ Конфигурация

### Переменные окружения

```env
# Основные настройки Redis
REDIS_URL=redis://localhost:6379
ENABLE_PERSISTENT_QUEUE=true

# Дополнительные настройки (опционально)
REDIS_MAX_CONNECTIONS=5
REDIS_CONNECTION_TIMEOUT=10
REDIS_SOCKET_TIMEOUT=30
```

### Приоритет конфигурации

1. **Переменная окружения** `REDIS_URL`
2. **Настройки бота** `settings.REDIS_URL`
3. **По умолчанию** `redis://localhost:6379`

## 🔧 Автоматическая оптимизация

Система автоматически определяет тип Redis сервиса и применяет оптимальные настройки:

### **Upstash**
- Ограничение соединений: 5 (для бесплатного тарифа)
- Проверка здоровья: каждые 30 секунд
- Pipeline операции для атомарности
- Ограниченное сканирование для экономии запросов

### **Локальный Redis**
- Стандартные настройки
- Блокирующие операции
- Полное сканирование данных

### **Другие внешние сервисы**
- Консервативные настройки
- Ограничение соединений: 3
- Проверка здоровья: каждые 60 секунд

## 🚨 Ограничения и рекомендации

### **Upstash (бесплатный тариф)**
- **10,000 запросов/день** - достаточно для ~100 активных пользователей
- **256MB RAM** - ограничивает количество задач в очереди
- **Рекомендации:**
  - Включите `ENABLE_PERSISTENT_QUEUE=true` только при необходимости
  - Мониторьте количество запросов через веб-консоль
  - Используйте для небольших проектов

### **Локальный Redis**
- **Неограниченные ресурсы** (зависит от сервера)
- **Требует администрирования**
- **Рекомендации:**
  - Для продакшена с высокой нагрузкой
  - При наличии DevOps команды
  - Для полного контроля над данными

### **Платные внешние сервисы**
- **Масштабируемость** и надежность
- **Техническая поддержка**
- **Рекомендации:**
  - Для коммерческих проектов
  - При высокой нагрузке (>1000 пользователей)
  - Для глобального распределения

## 🔍 Диагностика проблем

### **Ошибка подключения**

```log
ERROR - Failed to connect to Upstash Redis: Connection timeout
```

**Решение:**
1. Проверьте `REDIS_URL` в переменных окружения
2. Убедитесь, что сервис доступен
3. Проверьте firewall/сетевые настройки

### **Превышение лимитов Upstash**

```log
WARNING - Large task count (150) in Upstash, limiting status scan
```

**Решение:**
1. Увеличьте тариф на Upstash
2. Очистите старые задачи: `/admin` → **🗄️ Кэш** → **🗑️ Очистить кэш**
3. Оптимизируйте использование очереди

### **Fallback на in-memory**

```log
WARNING - Redis initialization failed, falling back to in-memory queue
```

**Решение:**
1. Проверьте подключение к Redis
2. Убедитесь, что `redis` пакет установлен: `pip install redis`
3. Проверьте права доступа к Redis

## 📈 Производительность

### **Метрики для мониторинга**

- **Hit rate** - эффективность кэша
- **Miss rate** - промахи кэша
- **Connected clients** - количество подключений
- **Used memory** - использование памяти

### **Оптимизация**

1. **Ограничьте размер очереди** для бесплатных тарифов
2. **Используйте pipeline** для batch операций
3. **Настройте TTL** для автоматической очистки
4. **Мониторьте** количество запросов к внешним сервисам

## 🔐 Безопасность

### **SSL/TLS**
- Все внешние сервисы используют SSL по умолчанию
- Локальный Redis может требовать дополнительной настройки

### **Аутентификация**
- Используйте сложные пароли для внешних сервисов
- Ограничьте доступ по IP (если поддерживается)
- Регулярно ротируйте пароли

### **Изоляция данных**
- Все ключи имеют префикс `gemaibot:`
- Данные изолированы от других приложений
- Возможность использования разных баз данных
