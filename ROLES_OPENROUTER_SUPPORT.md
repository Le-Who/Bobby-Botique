# Поддержка ролей (системных промптов) для OpenRouter

## Обзор

Системные промпты (роли) теперь полностью поддерживаются для моделей OpenRouter. Это включает:
- ✅ Предустановленные роли (teacher, it_engineer, doctor_info, и т.д.)
- ✅ Кастомные роли пользователей
- ✅ Генерацию новых кастомных ролей через AI
- ✅ Системные инструкции по умолчанию

## Как это работает

### 1. Применение ролей

Роли применяются одинаково для обоих провайдеров:

```python
# В chat_state сохраняется системный промпт
chat_state.system_prompt = prompts.compose_system_instruction(role_prompt)

# При запросе к AI системный промпт передается через system_instruction
system_instruction = prompts.compose_system_instruction(chat_state.system_prompt)
response = await _get_ai_response(..., system_instruction=system_instruction)
```

### 2. Формат системных промптов

Функция `compose_system_instruction()` комбинирует:
- Базовый системный промпт (`settings.DEFAULT_SYSTEM_PROMPT`)
- Дополнительную роль (если указана)

Результат одинаково работает для Gemini и OpenRouter.

### 3. Передача в OpenRouter

В OpenRouter системные промпты передаются как сообщение с `role="system"`:

```python
if system_instruction:
    messages.append({
        "role": "system",
        "content": str(system_instruction)
    })
```

Это стандартный формат OpenAI/OpenRouter.

## Обновленные компоненты

### 1. Генерация кастомных ролей

**Файл:** `app/handlers/messages.py`

**Было:**
```python
key_data = await db.get_available_gemini_key(chat_state.model)
response_text, _ = await get_gemini_response(...)
```

**Стало:**
```python
key_data, model_used, _ = await agent._resolve_ai_request(model_for_role)
response_text, _ = await agent._get_ai_response(...)
await agent._increment_key_usage(key_data['key_hash'], model_used)
```

Теперь генерация ролей использует выбранную пользователем модель (Gemini или OpenRouter).

### 2. Повтор генерации роли

**Файл:** `app/handlers/callbacks.py`

Аналогично обновлено для поддержки обоих провайдеров.

### 3. Применение ролей

Роли применяются через `chat_state.system_prompt`, который затем передается в `_get_ai_response()` через параметр `system_instruction`. Это работает автоматически для обоих провайдеров.

## Технические детали

### Функция compose_system_instruction

```python
def compose_system_instruction(role_prompt: Optional[str]) -> str:
    base = settings.DEFAULT_SYSTEM_PROMPT.strip()
    if role_prompt:
        return base + "\n\n# ДОПОЛНИТЕЛЬНАЯ РОЛЬ\n" + role_prompt.strip()
    return base
```

Эта функция работает одинаково для обоих провайдеров, так как возвращает простую строку, которая затем передается в соответствующий API.

### Передача в OpenRouter

В `_execute_openrouter_request()` системный промпт добавляется первым сообщением:

```python
if system_instruction:
    messages.append({
        "role": "system",
        "content": str(system_instruction)
    })
```

Это соответствует стандарту OpenAI, который поддерживается OpenRouter.

## Известные ограничения

1. **Длина системного промпта**: Некоторые модели OpenRouter могут иметь ограничения на длину системного промпта. Если системный промпт слишком длинный, может потребоваться его сокращение.

2. **Совместимость моделей**: Не все модели OpenRouter одинаково хорошо обрабатывают системные промпты. Рекомендуется тестировать с выбранной моделью.

3. **Форматирование**: Системные промпты передаются как простой текст. Специальное форматирование (Markdown, HTML) может не поддерживаться всеми моделями.

## Рекомендации

1. **Тестирование**: После выбора новой модели OpenRouter рекомендуется протестировать работу ролей
2. **Длина промптов**: Старайтесь создавать роли с умеренной длиной промпта
3. **Совместимость**: Если роль не работает с определенной моделью, попробуйте другую модель OpenRouter
