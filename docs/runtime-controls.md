# Управление моделями, инструкциями и алиасами

Состояние рабочего дерева на 2026-10-23. Панель `/controls` дополняет мониторинг
`/` и существующий Daily Admin. Этот документ описывает код; он не подтверждает
развёртывание на VPS или доступ к моделям у провайдера.

В панели доступны процессы, инструкции и каталоги голосов TTS. Исторические
инструкции показаны только для просмотра со ссылкой на замену. Embeddings
показываются только для просмотра: смена пространства векторов требует отдельной
миграции. Политики остальных процессов, каталоги моделей и голосов, инструкции и локальные
суточные пределы Gemini сохраняются в существующей таблице `global_settings`.
Новой SQL-миграции для этих настроек нет.

## Применение изменений

| Изменение | Момент применения | Ограничение |
| --- | --- | --- |
| Модель, порядок резервов, инструкция | Следующая операция | Начатая операция сохраняет свой снимок маршрутов и промптов |
| Каталог голосов TTS, голос по умолчанию, параметры | Следующая операция синтеза / чтение списка голосов | Уже начатая генерация сохраняет свою ревизию; выбранный пользователем действующий голос имеет приоритет |
| Алиасы команды | Следующее сообщение | Снимок фиксируется перед проверкой обработчиков; основная команда остаётся доступна |
| Live / Vertex Live | Новый голосовой сеанс | Активный transport не переподключается |
| Текст предустановленной роли | Новый выбор пресета | Сохранённые персональные копии не переписываются |
| Каталог пользовательского выбора | Следующее чтение каталога | Каталог не доказывает доступ к модели или совместимость каждого payload |
| Локальный Gemini RPD | Следующее резервирование | Счётчик уже потраченных запросов сохраняется; снижение ниже расхода запрещает новые обращения |
| Env, credentials, worker count, клиентские pools | Действующий механизм запуска | Редактор маршрутов не пересоздаёт стартовые ресурсы |
| Embedding model / dimension | Отдельная миграция | Пространства разных моделей нельзя смешивать даже при одинаковой размерности |

Кэш настроек на других экземплярах обновляется при следующем обращении, не чаще
чем раз в пять секунд. Это TTL, а не доставка обновления в гарантированный момент.
При ошибке хранилища сохраняется последний подтверждённый снимок с признаком
`degraded`. История и данные GET получаются из одной принятой ревизии.

Сохранение выполняется с `expected_revision`. Устаревший черновик получает 409
и остаётся в форме; перенос на актуальную ревизию требует сравнения пользователем.
Reset удаляет выбранный override. Restore создаёт новую ревизию и валидирует
действующие исторические значения перед записью; сохранённые значения удалённых
промптов и процессов остаются неактивными. Другие черновики и фокус сохраняются
при обновлении данных; полная перезагрузка страницы для сохранения не нужна.

Правки, введённые во время сохранения, остаются новым черновиком: ответ сервера
подтверждает только отправленную версию. Если POST принят, а последующий GET
не удался, панель явно сообщает о сохранении на сервере и сохраняет буфер.
Новые записи блокируются до успешного «Обновить данные». Запоздавший GET,
начатый до записи, не заменяет текущую форму и не скрывает ошибку сохранения.

## Работа с панелью

- Каждый раздел открывается отдельно. На desktop используется боковое меню,
  на mobile — закреплённый выбор раздела; кнопка обновления доступна в обоих режимах.
- Раздел, поисковый запрос и группа отражаются в URL. «Назад» возвращает состояние
  фильтров; смена раздела не сбрасывает черновики и не загружает документ заново.
- «Команды и алиасы» (`/controls#commands`, ссылка «Команды» в мониторинге)
  показывает команды текущего экземпляра бота, включая служебные и команды
  внутри диалогов. Поиск учитывает команду, алиасы, текстовые правила и обработчик;
  фильтр отделяет публичное меню от остальных входов. Наличие команды вне меню
  само по себе не определяет её права доступа.
- Процессы упорядочены по назначению, основные chat/inline идут первыми.
  Поиск учитывает текущий черновик, включая ещё не сохранённые model ID и текст.
- Локальный черновик можно отменить отдельно от сброса серверного override.
  Перемещение/удаление модели сохраняет клавиатурный фокус; уход с несохранёнными
  изменениями вызывает стандартное предупреждение браузера.
- Restore требует подтверждения с явным указанием, что восстанавливает всю
  конфигурацию. Исторические инструкции не принимают новые save/reset;
  старые значения остаются совместимыми с загрузкой истории.
- Вкладки мониторинга поддерживают стрелки, Home/End, прямые ссылки и «Назад».
  На узком экране видны все четыре вкладки. Устаревший/недоступный snapshot
  получает отдельные текст и цвет, не сохраняет зелёный признак LIVE.
- Обновление мониторинга допускает один активный HTTP-запрос; через десять секунд
  браузер отменяет зависший запрос и разрешает следующий. SSE читает те же действующие
  счётчики запросов и очереди. Замер CPU и памяти выполняется вне event loop.
  Дневные метрики складывают уже сохранённые итоги и ещё не записанные события;
  успешная периодическая запись не обнуляет видимый дневной итог.
- Workload разделяет пользовательские операции и отправки API, с календарными
  периодами по Киеву и явным неполным историческим покрытием. Модели Gemini
  свёрнуты в группы с поиском, сортировкой и расходом каждого ключа внутри.
  Периоды, источники, область учёта и восстановление описаны в
  [метриках и мониторинге](metrics-and-dashboard.md).

## Диагностика моделей

Раздел **«Диагностика моделей»** (`/controls#diagnostics`) объединяет сохранённые
назначения в процессах, членство в пользовательских каталогах, локальный Gemini RPD
и записанные состояния пар ключ/модель. Назначение в маршруте не означает, что
модель уже вызывалась; наличие в каталоге не подтверждает доступ у провайдера.
В карточке показаны основные и резервные назначения, а ссылки открывают нужный
процесс. Несохранённый черновик маршрута не заменяет сохранённые назначения.

Счётчики RPD относятся к локальному общему учёту Gemini и суткам Pacific Time.
Это резервирования запросов, включая гонки и повторы, а не биллинг или число
готовых ответов. При отсутствии строк показывается «Нет данных RPD».
Допуск по RPD, приостановка ключа и внешний доступ представлены отдельно.
Порог допуска может быть ниже суточного предела: блокировка по порогу не означает
полного исчерпания лимита. Истёкшая приостановка допускает новые попытки, но
сама по себе не подтверждает успешный новый вызов.

Учёт загружается одним общим snapshot при первом открытии раздела; повторный
переход использует тот же снимок. Кнопка обновления получает свежие данные,
параллельные запросы не запускаются. При ошибке прежние данные остаются с явным
признаком устаревания; отсутствующие источники и неполная выборка состояний
не превращаются в нулевые значения или подтверждение исправности.
Различие ревизий настроек и RPD, а также degraded-конфигурация отмечаются отдельно.
Фильтры выделяют модели с ограничениями, назначенные модели и модели без учёта RPD.
Диагностика не отправляет платные пробные запросы к провайдерам.

В HTTP snapshot каждому асинхронному источнику отведено пять секунд. Недоступный
источник возвращает безопасный код ошибки, а остальные разделы остаются доступны.
Отмена cooperative: обработка отмены и очистка ресурсов могут добавить время
после срока. Состояния сервисов задаёт этот проверенный snapshot; SSE обновляет
оперативные счётчики и не заменяет результат probe наличием открытого пула.
Статистика пула использует публичные счётчики asyncpg;
число Redis-ключей относится к выбранной базе подключения.
Холодная загрузка лимитов выполняется одним SQL-запросом для всех cache misses;
приоритет admin override, включая `null`, и env/DB baseline сохраняется.

[Аудит промптов](prompt-quality-audit-2026-10-02.md) фиксирует перечень
90 ID на дату аудита, соответствие исполнителям, исправленные примеры/инструкции и границы
проверки. Дополнительные presets охватывают гороскоп, ежедневную image scene,
inline search/tabs, продолжение ответа и классификацию расшифровки.

## Голосовые сообщения и TTS

Раздел **«Голоса и TTS»** (`/controls#audio`) управляет отдельными каталогами
Gemini и ElevenLabs: добавление, исправление ID и названия, удаление, перемещение
вверх/вниз и выбор голоса по умолчанию. Это упорядоченные списки для Mini App;
порядок резервирования провайдеров и моделей задаётся в **«Процессах»**.
ID добавляются вручную и должны поддерживаться провайдером и его аккаунтом.
Сохранение каталога не выполняет платный запрос и не подтверждает доступ к голосу.

Параметры Gemini: общая температура TTS (0–2) и `max_output_tokens` (1024–16384,
в пределах [выходного лимита текущей модели](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash-lite-tts)).
Приоритет значения: явная пользовательская настройка → индивидуальная настройка
голоса → общая температура. Индивидуальное поле необязательно: старые сохранённые
каталоги без него продолжают использовать общую настройку. Значение выбирает
нейтральную (≤0.3), выразительную (≥0.8) или разговорную инструкцию.
Для Gemini 3.8 sampling temperature не передаётся; у прежних моделей сохраняется
минимум температуры API 0.5.
У каждого голоса Gemini есть дополнительный свободный промпт до 4000 байт UTF-8:
он входит в общую инструкцию произношения и стиля. В Gemini 3.8 инструкции
передаются как короткое направление подачи в `speech_metadata.style`, отдельно
от дословно читаемого текста. Восемь baseline-голосов имеют индивидуальные
инструкции; подробный текст `tts.director` применяется только к прежним моделям
с префиксом GenerateContent. Стили `tts.style.*`, темп `tts.pacing.*` и legacy
правила `tts.director` редактируются в **«Инструкциях»**. Чрезмерно длинные
режиссёрские указания не добавляются к стилю Gemini 3.8. Выбранные значения —
стартовые профили подачи; качество конкретного голоса требует прослушивания.

Для ElevenLabs доступны `stability`, `similarity_boost`, `style` (0–1),
`use_speaker_boost` и нормализация текста (`auto`, `on`, `off`). Эти параметры
применяются ко всем голосам ElevenLabs. Отдельный промпт стиля этот путь
`/v1/text-to-speech/{voice_id}/stream` не передаёт: текст запроса озвучивается.
При необходимом делении длинного текста соседние части дают до 500 символов
контекста с каждой стороны для связной речи.

Без override используются восемь прежних голосов Gemini и семь прежних
предустановок ElevenLabs; `ELEVENLABS_VOICE_ID` остаётся baseline голоса по
умолчанию и при необходимости добавляется в baseline-каталог. `/webapp/api/voices`
теперь возвращает управляемый каталог первого настроенного в `tts.delivery`
провайдера (ElevenLabs без ключей пропускается), его ID и `default_voice`.
Автоматическая подмена списка результатом ElevenLabs `/v1/voices` удалена:
пользователь и администратор видят один и тот же порядок. Персональные промпты
голосов в пользовательский ответ API не попадают.

Пустая пользовательская настройка использует административный default.
Удалённый из каталога голос также заменяется default соответствующего провайдера;
неизвестный ID при новом сохранении пользовательских настроек отклоняется.
При переходе с ElevenLabs на Gemini используется Gemini default, если выбранного
ID нет в его каталоге. Провайдер определяется маршрутом и членством ID в каталоге;
длина ID больше не определяет его тип.

Настройки хранятся как `audio:gemini` и `audio:elevenlabs` в том же versioned
документе `global_settings`, что модели и инструкции. Доступ, CSRF, проверка
ревизии, история, reset и restore общие. Reset возвращает кодовые/env defaults.
Кэш между экземплярами имеет тот же TTL до пяти секунд; запущенное TTS-задание
сохраняет снимок каталога, параметров и промптов на протяжении всего синтеза.

Модели без административных/env переопределений:

| Назначение | Процесс в панели | Базовая цепочка |
| --- | --- | --- |
| Провайдеры синтеза | `tts.delivery` | ElevenLabs → Gemini |
| ElevenLabs TTS | `tts.elevenlabs` | `ELEVENLABS_MODEL`, default `eleven_multilingual_v2` |
| Gemini TTS | `tts` | `gemini-3.8-flash-lite-tts` → `gemini-3.8-flash-tts` |
| Провайдеры распознавания | `asr.delivery` | Pollinations → Gemini |
| Pollinations ASR | `asr.pollinations` | `whisper` |
| Gemini ASR | `asr` | `gemini-3.1-flash-lite` → `gemini-3.5-flash` |
| Намерение после распознавания | `media.intent` | `gemini-3.1-flash-lite` → `gemini-3.5-flash` → `opencode-go/big-pickle` |
| Неоднозначная просьба об озвучке | `intent.voice` | `OPENCODE_INLINE_MODEL`, default `opencode-go/minimax-m2.5`; без него — `OPENCODE_QNA_MODEL` |

Распознавание также использует управляемые инструкции `media.asr` и
`media.intent.text`; классификация просьбы об озвучке —
`intent.voice` и `intent.voice.system`. Этот классификатор относится к просьбе
озвучить генерируемый ответ. Прямая озвучка переданного текста сначала
разрешается локально через `SpeechRequestIntent`: текст сообщения, reply или
пересылки без вызова модели, текстового повтора и перефразирования. Если источник
неясен, обработчик просит уточнение без классификатора. Правила и примеры —
в [руководстве по озвучке](voice-and-tts.md). Отдельное распознавание для памяти
использует процесс `media.memory_voice` и инструкцию `media.voice_memory`.
Управление моделями Live Audio (`live`, `live.vertex`) и его инструкциями остаётся
в существующих разделах; каталог голосов Live и системный браузерный TTS Reader
не относятся к каталогам синтеза Telegram-ответов.

Очередь Telegram TTS хранится в процессе: до 8 заданий на пользователя,
128 всего, 64 КиБ UTF-8 текста на задание и 8 МиБ удерживаемого текста суммарно.
Активные задания входят в эти пределы. Перегрузка и остановка возвращают отказ;
кнопка чтения сообщает, что повторить запрос нужно позже. Перезапуск процесса
не восстанавливает очередь. Отзыв согласия отменяет соответствующее задание,
удаляет его текст и не блокирует следующие действующие задания пользователя.

На синтез и упаковку задания отведено от 300 до 900 секунд по подтверждённому числу частей,
включая ожидание доступного провайдера. Для разных пользователей одновременно
выполняются до трёх фактических Gemini-запросов; внутри одного задания и
пользовательской очереди части генерируются последовательно, без гонки ключей.
Ответ модели принимается
только при завершённой генерации всех частей сообщения. Каждый результат
проверяется как mono PCM 24 кГц / signed 16-bit little-endian; совместимый WAV
разбирается по метаданным. Предел аудио — 32 МиБ на ответ и полное сообщение.
Неполные, несовместимые и слишком большие результаты не отправляются.

Gemini 3.8 использует Interactions с `store=False`, явным `audio/l16` и SDK
не ниже 2.25.0. Очередь хранит до 64 КиБ UTF-8 текста на задание; один вызов
ограничен входным/выходным токенным бюджетом с учётом инструкций.
Направления дополнительно ограничены 7500 байтами. Расчёт частей и сроков
описан в [правилах фонового синтеза](#снимки-настроек-в-фоновой-работе). Слишком длинная
административная инструкция требует сокращения. Явно выбранные прежние модели
поддерживаются через GenerateContent. Уже сохранённая административная цепочка
сохраняет свой порядок и не заменяется новым baseline автоматически.

Telegram получает готовый OGG/Opus целиком. Потоковое чтение ElevenLabs ограничивает
потребление памяти и время ожидания, но не запускает проигрывание до готовности
файла. После отправки очередь сразу продолжает работу; удаление статуса через
пять секунд выполняется отдельно, без текста задания и его consent lease.

## Источник и порядок маршрута

Без административного override сохраняется прежнее поведение исполнителя.
Явная политика задаёт точную цепочку и не добавляет скрытый резерв из каталога.
Список резервов нельзя оставлять пустым: одна модель означает выполнение без
резервной модели. Пользовательская primary учитывается только при включённом
наследовании; редактор порядка провайдеров речи не наследует model ID.

Auto Крокодила сохраняет адаптивный путь классической игры; ежедневная генерация
имеет свой default. Поэтому пустой baseline в карточке Auto не является
отсутствием исполнителя. Старые формы Крокодила, inline и Daily Trivia используют
согласованные versioned writers; смена primary сохраняет остальные резервы.
Сброс каталога атомарно помечает возврат к env и не оживляет старую запись v2.

| Граница | Исполнитель / исходники |
| --- | --- |
| Chat, search, document, vision, inline | `app/providers/router.py`, `app/handlers/ai_*.py`, `app/handlers/inline.py` |

## Автоматическая инвентаризация

`app/runtime_settings/source_inventory.py` разбирает Python-файлы внутри `app/`
без исполнения их содержимого. Индекс создаётся один раз на экземпляр процесса:
изменения исходников видны после запуска новой версии, а не после reload настроек.
Он находит модульные определения `register_controlled_text`, прямые чтения
инструкций и вызовы поддерживаемых исполнителей с явным ID, включая условный
выбор между строковыми ID. Определения и места чтения показываются в карточках
промптов с файлом, функцией и строкой. Модули определений импортируются автоматически;
ручного списка в загрузчике больше нет. Первое чтение исходников и импорт идут
в рабочем потоке, вне асинхронного пути обработки запроса.

Новый вызов с неизвестным process ID появляется в панели только для просмотра
и проваливает проверку покрытия. Возможности модели, ограничения транспорта,
правила резервирования и момент применения описывает разработчик в `PROCESSES`
и семантической карте: анализ строк не может безопасно придумать эти контракты.
Проверка также обнаруживает оставшийся зарегистрированный процесс после удаления
его явных consumers. Динамический ID, имя через переменную, произвольная
композиция или ветвь недостижимого кода требуют проверки разработчиком. Индекс
не доказывает выполнение пути и не устанавливает, что любой шаблон без прямого
строкового обращения больше не используется.

При удалении функции удаляйте её ненужные регистрации в том же изменении.
В новой версии удалённое определение исчезает из каталога; сохранённый override
такого ID остаётся в `global_settings`, но не применяется и не блокирует другие
промпты. Override удалённого процесса также остаётся неактивным; такие значения
не блокируют восстановление действующих настроек из истории.
Уже известные исторические шаблоны с указанными заменами продолжают
показываться только для просмотра. Инвентаризация не удаляет сохранённые значения
и историю настроек из базы данных.

`app/command_inventory.py` собирает команды из живого `Application`, а не из
второй вручную заполненной таблицы. Он обходит `CommandHandler` и вложенные
`ConversationHandler`, связывает текстовые `MessageHandler` с их callbacks и
сохраняет контекст регистрации и полные фильтры. `/tarot`, `/таро`, `/расклад`,
«таро», «натальная», `/карта`, `/draw` и его алиасы отражают действующие правила
обработчиков. Примеры текстовых алиасов не исчерпывают регулярное выражение;
полный pattern и флаги раскрываются в карточке. Отрицательное Regex-условие
не становится алиасом. Явные текстовые кнопки и переключения режима внутри диалога
также показаны; обычные поля ввода не выдаются за команды.
Собственные фильтры фиксированных текстовых входов, например завершение сеанса
Таро, объявляют статические поля inventory_pattern и inventory_aliases на классе
со ссылками на используемые ими Regex и тексты кнопок. Это позволяет добавлять
такие входы без второго списка в дэшборде и без чтения состояния пользователя.
Свободные намерения, распознаваемые ИИ, и служебные callback data относятся к
другим входным границам и не перечисляются как slash-команды.

GET `/api/admin/controls/commands` требует административную web-авторизацию,
читает регистрации и снимок настроек из `global_settings`, без обращения к Telegram
или пользовательским данным. Основной GET `/api/admin/controls` включает этот
каталог в той же принятой ревизии, что модели, промпты и история. До регистрации
бота возвращается явный признак недоступности. При обновлении страницы добавленные
и удалённые обработчики отражаются автоматически.
Проверки покрытия входят в обычный pytest-набор; отдельно их можно запустить:

```bash
uv run --locked pytest tests/test_source_inventory.py tests/test_command_inventory.py --override-ini="addopts=" --timeout=30
```

## Редактирование алиасов

В разделе «Команды и алиасы» у команд с однозначной регистрацией есть поле
«Алиасы — по одному на строке». Можно добавить новое название, заменить или
удалить существующее. Например, для `/draw` можно сохранить `/paint`, `/рисуй`
и «нарисуй». Основная `/draw` продолжит работать и останется в публичном меню;
алиасы не добавляют отдельные строки меню Telegram.

«Проверить алиасы» проверяет формат и пересечения без записи. «Сохранить алиасы»
создаёт общую ревизию настроек. «Отменить черновик» возвращает загруженный список,
а «Вернуть исходные алиасы» удаляет override и возвращает регистрации из кода.
Пустой сохранённый список отключает алиасы, сохраняя основную команду. После
сохранения исходные положительные текстовые правила этой команды принимают
только перечисленные алиасы; сброс возвращает исходные Regex, включая их вариации.
Текстовые кнопки и входы с неоднозначным общим обработчиком показаны только для
просмотра, с объяснением в карточке.

Допускается до 40 алиасов на команду. Slash-название содержит 1–32 буквы, цифры
или подчёркивания после `/`, включая кириллицу. Суффикс `@botname` и аргументы
не включаются в настройку: при обращении slash-алиас проверяет имя бота и
передаёт аргументы исходному обработчику. Текстовый алиас — целая фраза до 80
символов без `/`, `@` и управляющих символов; регистр и повторные пробелы
нормализуются. Новые текстовые входы для команд без исходного текстового правила
работают только в личном чате. Форматы ввода даты зарезервированы за личными
формами и не принимаются как текстовые алиасы.

Повторы, основные команды, алиасы и текстовые правила других входов защищены
от пересечений. Проверка всей кандидатной конфигурации выполняется внутри
versioned writer до CAS-записи. Редактирование сохраняет callbacks, ограничения
чата, авторизацию, правила аргументов, порядок групп и переходы ConversationHandler.
`app/command_aliases.py` устанавливает поддержку после регистрации в `bot.py`,
до инициализации бота; обработчики читают неизменяемый снимок операции, без
изменения глобального списка команд при каждом сообщении.

Алиасы сохраняются под ключами `command_aliases:<id>` в существующем документе
runtime controls. SQL-миграция не нужна. Restore восстанавливает их вместе
с остальной конфигурацией и повторно проверяет конфликты; записи удалённых команд
остаются неактивными. Черновики сохраняются при обновлении, конфликте ревизий
и вводе во время сохранения. При подтверждённой записи и неудачном GET панель
блокирует новые изменения до успешного обновления данных.

```bash
uv run --locked pytest tests/test_command_aliases.py tests/test_web_controls.py tests/test_controls_commands_browser.py --override-ini="addopts=" --timeout=30
```

## Снимки настроек в фоновой работе

Долгоживущие workers не наследуют снимок настроек первого enqueue. Голосовой FIFO
и предзагрузка подсказок фиксируют новую ревизию для каждого задания, сохраняя
контекст трассировки и privacy lease. Подготовка ежедневных игр через HTTP и
scheduler также фиксирует общий снимок на все стадии. Повтор создания роли
применяет ту же `roles.generate`, что и первоначальная генерация.

Медиапроцессы сохраняют специальные endpoint, аудиоформат, voice и
параметры изображений. ElevenLabs при смене модели начинает полное сообщение
заново. Gemini TTS делит очищенный текст по входному и выходному бюджету,
генерирует необходимые части последовательно и собирает один файл для задания.
Ключи перебираются последовательно при отказе квоты или ошибке провайдера.
Прежнее фиксированное разбиение по 800 байт и гонки ключей удалены. ElevenLabs
делит только текст сверх известного символьного лимита выбранной модели:
10 000 для Multilingual v2, 40 000 для Flash v2.5. При смене модели лимит и число
частей рассчитываются заново. Между необходимыми частями сохраняется контекст;
у неизвестной модели ограничение проверяет провайдер. Прямые Gemini
цепочки и явные ASR/intent планы ограничены общим сроком 120 секунд и числом попыток ключей; более короткий
срок вызывающего процесса сохраняется. Это не обещание такого срока для всех
исторических исполнителей без override.
Gemini TTS-цепочка начинает с общего двукратного timeout одной попытки.
Срок увеличивается по подтверждённому числу необходимых частей, максимум
870 секунд. Истечение срока отменяет текущую попытку, дожидается её очистки
и разрешает следующий выбранный провайдер доставки. Обычное задание имеет
300 секунд; при подтверждённом делении срок может вырасти до 900 секунд.
Внутренние части не получают отдельные бесконечные сроки.

Очередь принимает источник до 64 КиБ UTF-8. Это предел памяти задания, отдельно
от лимитов одного API-вызова. Перед Gemini TTS вызывается `countTokens` именно
выбранной TTS-модели с входным пределом 8192 токена. Текст, направления подачи,
голос и язык передаются счётчику явными текстовыми частями: speech-аннотации
сами по себе не дают полного подсчёта метаданных. Это консервативный подсчёт
токенов всего текстового материала, без замены токенов байтами и без генерации
текста. Направления дополнительно ограничены 7500 байтами по памяти приложения.

Помещающийся источник отправляется целиком. Только измеренное превышение входа
запускает подбор допустимых границ предложений/слов с проверкой токенов частей;
порядок и разделители сохраняются. Подбор ограничен 17 частями и 64 запросами
счётчика на задание. Результаты хранятся как ограниченные hash-only записи,
связанные с моделью, исходным текстом и метаданными, без глобального кэша частного
текста. Проверка короткого хвоста может передать такую запись в очередь; при
совпадении данных синтез не повторяет подсчёт. Очистка задания удаляет и записи.

Подсчёт использует не более 10 секунд и 20% срока одной попытки. Если сервис
подсчёта недоступен, обычный источник передаётся целиком для проверки самим TTS
API в оставшийся срок. Байтовый порог не возвращается, а объединение хвоста
при неизвестном результате не разрешается. Сбой счётчика не приостанавливает
ключ; фактические запросы подсчёта учитываются отдельно от генераций и не
резервируют их локальные RPM/RPD.

Настроенный `max_output_tokens` (1024–16384) передаётся в аудиогенерацию как
выходной предел. Порог 2621 байт, резерв половины длительности и перевод текста
через 8 байт/сек удалены. Будущую длительность нельзя точно вывести из текста,
поэтому уменьшение выходного бюджета не создаёт заранее крошечные части.
Низкий предел может потребовать фактического отказа/обрезания и дальнейшего деления.

Явный незавершённый или достигший выходного лимита ответ отбрасывается. Тот же
текст делится ближе к середине по пробельной границе и пробуется последовательно,
без наказания здорового ключа за длину текста. Предел — 16 дополнительных
разделений и глубина 4 на модель, без дальнейшего деления частей до 32 байт;
если закончить источник не удалось, его частичное
аудио не отправляется. Фрагменты, состоящие только из пробельных разделителей,
не требуют собственного вызова API и не увеличивают число озвучиваемых частей.
Завершённые PCM-части соединяются без нахлёста и обрезания
речи, затем кодируются в один OGG. Это не обратная проверка всех произнесённых
слов: незаявленный пропуск или добавление речи требует прослушивания/ASR.
Контракты провайдера: [карточка Gemini TTS](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash-lite-tts)
и [учёт аудиотокенов](https://ai.google.dev/gemini-api/docs/pricing).

`GEMINI_TTS_RPM_PER_KEY` задаёт локальный бюджет Gemini TTS на ключ и модель в
скользящем окне 60 секунд (по умолчанию 3, положительное целое, нужен перезапуск).
У Google лимиты [применяются к проекту](https://ai.google.dev/gemini-api/docs/rate-limits),
поэтому такой раздельный учёт соответствует текущей конфигурации пула: каждый
ключ принадлежит отдельному проекту. Несколько ключей одного проекта не дают
дополнительного RPM и потребовали бы общего идентификатора квоты.
Свободные слоты — максимум минус отправленные за окно запросы и удерживаемые
резервы. Резерв создаётся для очередной необходимой TTS-части до отправки;
вся длинная очередь заранее не занимает будущие минутные окна.
VPS workflow передаёт его в контейнер. Redis атомарно резервирует минутные слоты
между экземплярами; без Redis действует локальный учёт. Ошибка Redis имеет
неопределённый исход и не разрешает обход через локальный бюджет. Незавершённый
допуск удерживается до deadline попытки; непосредственно перед SDK окно обновляется
на полные 60 секунд, поэтому ожидание RPD в БД его не сокращает.
При отказе RPD или отмене до отправки минутный резерв освобождается только своим
владельцем. После отправки расход RPM сохраняется до истечения окна, а RPD — до
смены суток, включая ошибки и отмену. Неопределённый результат записи RPD учитывается
консервативно; повторное списание после успешного ответа не производится.
Внутренние retry SDK отключены отдельно для TTS: один допуск соответствует одному
HTTP-запросу. Ключи выбираются заново по текущему расходу; пул не ограничен четырьмя
попытками. Локальный отказ не приостанавливает ключ. Когда все доступные ключи
временно заняты по RPM, очередь ждёт ближайшего окна в пределах общего deadline.
Для HTTP 429 только явный суточный предел даёт приостановку до смены суток;
минутный и неопределённый rate limit используют короткий cooldown.

## Промпты и квоты

Для текстовых Gemini 3 применяется общий model-aware builder
`app/providers/gemini_config.py`, в том числе в прямых SDK-потребителях.
Он оставляет sampling на стороне провайдера и не отправляет `temperature`,
`top_p`, `top_k` и `candidate_count`; legacy Gemini 2.5 сохраняет свои параметры.
Это соответствует [рекомендации Google](https://ai.google.dev/gemini-api/docs/whats-new-gemini-3.6#api-changes-and-parameter-updates):
начиная с 3.5 Flash-Lite / 3.6 Flash sampling игнорируется и в следующих поколениях
может приводить к HTTP 400. Качество и формат задаются инструкцией и схемой ответа.
У Gemini 3.8 режим `minimal` заменяется на поддерживаемый `low`; у Gemini 3 Pro
учитываются его допустимые уровни, а Gemini 2.5 Pro с выбором `off` сохраняет
минимальный поддерживаемый бюджет 128 вместо запрещённого нуля. У небольших
текстовых запросов 3.8 без явной thinking policy задан `low` и не менее 1024
выходных токенов: этот предел включает reasoning и финальный ответ. Инструкция
и схема по-прежнему ограничивают формат короткого результата; это не замер
фактического расхода. Голосовые, Live и image-пути имеют отдельные
контракты и этот текстовый builder не используют.

Редактор показывает baseline, текущий текст, источник и обязательные переменные.
JSON-примеры допустимы; подстановка выполняется один раз, поэтому скобки внутри
пользовательского текста не превращаются в дополнительные переменные. Output
schemas, consent, provenance и transport config остаются контрактами кода.
Правка предустановленной роли не переписывает личную копию пользователя.
Кэши Крокодила учитывают связанные маршруты и инструкции; чужой лимит их не сбрасывает.
Редактор охватывает и forced synthesis research при исчерпании итераций.

Gemini RPD в панели — локальный предел бота на модель и ключ, с существующим
резервированием перед SDK attempt. Неуспешная попытка тоже расходует резерв.
Это не официальная квота проекта и не общий предел всех провайдеров.
Резервирование действует и без override маршрута для фоновых текстовых Gemini,
ASR/обработки медиа и Gemini TTS; локальный отказ не штрафует здоровье ключа.
Embeddings и Live не резервируют общий счётчик и исключены из этой формы.
Список лимитов включает модели внутренних политик вне пользовательского каталога.
Таблица usage читает runtime override, включая `null`, и тот же целочисленный
admission threshold. В ней также видны модели с расходом сегодня, даже если их
уже убрали из каталога. RPD availability не подтверждает provider access/health.
Изображения имеют независимые `IMAGE_GEN_RPD_PER_KEY` и `IMAGE_GEN_DAILY_LIMIT`;
они не меняются этой формой. Резервирование изображений в Redis атомарно.
Ошибка Redis имеет неизвестный исход записи и даёт `quota_unavailable`,
без обхода через локальный счётчик. Локальный режим используется при отсутствии
настроенного Redis и не обеспечивает общий предел нескольких процессов.

## Переход на очередь с владением

Новые workers используют уникальный owner, lease на 60 секунд с продлением
каждые 15 секунд и свой processing list. Claim, ACK/NACK и recovery проверяют
владение атомарно. Только истёкший owner может быть восстановлен другой репликой.
Потеря lease отменяет принадлежащие Redis-задачи; локальные задачи продолжаются.
Recovery допускает повторное выполнение: это семантика at-least-once.

Старый `gemaibotv2:processing` не имел owner и не восстанавливается автоматически.
Порядок эксплуатационного перехода:

1. Остановить приём новых jobs старыми workers и дождаться окончания их текущих
   обработчиков. Проверить все реплики, а не только один контейнер.
2. Убедиться, что ни один старый worker больше не читает и не подтверждает старый
   processing list. Сохранить защищённый recoverable снимок Redis штатным способом;
   не выгружать тела задач в публичные логи или отчёты.
3. Отдельной управляемой операцией вызвать
   `TaskQueue._recover_processing_tasks(recover_legacy=True)` после drain.
   Это внутренний API, не кнопка обычного запуска. Проверить остаток старого списка
   по количеству и агрегированным статусам: malformed записи сохраняются.
4. Запустить новые workers и проверить завершение восстановленных задач, отсутствие
   чужих ACK и повторной доставки. Не удалять processing keys вручную.

Статистика различает Redis, memory, mixed и недоступность Redis. Неизвестный размер
backlog не представляется нулём. Running/completed counters относятся к текущему
процессу; их нельзя трактовать как глобальную статистику всех реплик.

## Процедура смены embeddings

Текущая конфигурация: `gemini-embedding-2-preview`, 768 измерений,
`app/repos/memory_config.py`. Вектора памяти и графа используют `halfvec(768)`;
Daily Trivia также хранит embeddings. Старые migrations 008b/024 содержат
деструктивные исторические переходы и не являются процедурой новой смены модели.

1. Зафиксировать target model, размерность, task types, стоимость и критерии качества
   поиска. Проверить совместимость API отдельно от совместимости пространства.
2. Подготовить уникальную SQL-миграцию для параллельных новых столбцов/индексов и
   версии embedding space. Сохранить прежние векторы для rollback; не очищать LTM.
3. В изолированной базе проверить schema/RLS, tenant context, сохранение source IDs,
   consent epochs и live provenance. Внешние вызовы готовят результаты до write transaction.
4. Переиндексировать только разрешённые живые источники с durable leases,
   ограничением запросов и возобновляемыми checkpoint. Охватить память, граф,
   predicate/source embeddings и использующие тот же space банки вопросов.
5. Сравнить retrieval и дедупликацию на изолированных сценариях. Переключить
   query и document embeddings согласованно; смешанный поиск запрещён.
6. После отдельного разрешения на production migration выполнить drain/cutover,
   проверить результат и сохранить rollback до окончания периода наблюдения.

Эта процедура не запускается панелью. Изменение константы модели само по себе
не мигрирует уже записанные данные.
