# Надёжный выбор модели для Daily Trivia

## Контекст и подтверждённая причина

Админская страница Daily Trivia сохраняет значения `gemini-primary` и
`gemini-economy` в `global_settings.daily_trivia_llm_model`. Это внутренние
роли, а не идентификаторы моделей Gemini API.

До коммита `84ab47a` статическая allowlist-нормализация молча заменяла оба
алиаса fallback-моделью, поэтому `gemini-economy` фактически не гарантировал
экономичную модель. После перехода на синтаксическую проверку оба алиаса стали
похожи на допустимые model ID и начали передаваться в Gemini буквально. В
зафиксированном сбое `gemini-primary` получил `404 NOT_FOUND`.

Gemini provider вернул этот сбой как tagged-текст `[GENERIC]...`. Генератор
Daily Trivia не проверил error tag, нашёл первые квадратные скобки и попытался
разобрать `[GENERIC]` как JSON. Поэтому первичная ошибка модели была скрыта
вторичной `JSONDecodeError`.

## Цели

1. Сохранить стабильные role-алиасы `gemini-primary` и `gemini-economy`.
2. Разрешить администратору закрепить за Daily Trivia прямой Gemini model ID.
3. Проверять прямой model ID до сохранения и не записывать неподдерживаемое
   значение.
4. Использовать одну настройку для ручной и автоматической генерации.
5. Гарантировать известную fallback-цепочку независимо от видимости моделей в
   пользовательском каталоге.
6. Не маскировать ошибки провайдера ошибками JSON-парсинга.

## Семантика выбранного значения

`daily_trivia_llm_model` хранит одно из двух видов значений:

- `gemini-primary` — динамическая роль, которая при каждом вызове разрешается в
  текущий `GEMINI_PRIMARY_MODEL`;
- `gemini-economy` — динамическая роль, которая разрешается в текущий
  `GEMINI_ECONOMY_MODEL`;
- прямой ID вида `gemini-3.7-flash` — закреплённая модель, которая не меняется
  при последующем обновлении role-констант.

Такое различие намеренное: алиас следует за ролью, а прямое имя фиксирует
точный выбор администратора. Legacy-значения из БД продолжают работать без
миграции.

Прямой override относится только к Daily Trivia. Он не добавляет модель в
глобальный selectable-каталог `/models` и не меняет модель пользовательских
чатов.

## Админский интерфейс и сохранение

Текущий закрытый `<select>` заменяется редактируемым полем с подсказками
(`input` + `datalist`). Подсказки содержат оба role-алиаса и актуальные Gemini
модели из каталога, но не ограничивают ручной ввод нового ID.

Endpoint сохранения выполняет следующие шаги:

1. Trim и проверка непустого значения.
2. Для role-алиаса — разрешение через общую alias-нормализацию без сетевого
   запроса.
3. Для прямого ID — синтаксическая проверка и существующая Gemini capability
   validation через Models API; обязательна поддержка `generateContent`.
4. Только после успешной проверки — запись исходного значения в
   `daily_trivia_llm_model`.

Неподдерживаемая модель возвращает понятный `400`; временная невозможность
проверки — `503`. В обоих случаях прежняя настройка сохраняется. Успешный ответ
возвращает сохранённое значение, чтобы UI отражал серверное состояние.

## Маршрутизация и fallback

Общая нормализация Gemini получает явную таблицу совместимости:

- `gemini-primary` → `GEMINI_PRIMARY_MODEL`;
- `gemini-economy` → `GEMINI_ECONOMY_MODEL`.

Синтаксически корректные прямые ID по-прежнему проходят без статической
allowlist. Для выбранной модели формируется детерминированная цепочка:

`gemini-3.6-flash → gemini-3.5-flash → gemini-3.5-flash-lite → gemini-3.1-flash-lite`.

Если preferred model не входит в эту известную цепочку, например
`gemini-3.7-flash`, она вызывается первой, после чего используются все элементы
цепочки в указанном порядке. Если preferred model уже входит в цепочку,
используются только следующие элементы. Поэтому:

- `gemini-primary` начинает с текущей primary-модели и затем идёт вниз;
- `gemini-economy` начинает с текущей economy-модели и затем идёт вниз;
- `gemini-3.7-flash` идёт через `3.6`, `3.5`, `3.5-lite`, `3.1-lite`.

Известные fallback-модели являются внутренними runtime-кандидатами и не
фильтруются через `AVAILABLE_MODELS`: этот список управляет видимостью в
пользовательском selector, а не надёжностью служебных задач. Одинаковый порядок
закрепляется в key-resolution и typed router helpers, чтобы старый и новый пути
вызова не расходились.

## Обработка ответа провайдера

`generate_question_lane()` проверяет `is_error_message(response_text)` до
поиска JSON. Tagged error очищается через `strip_error_tag()` и превращается в
понятную ошибку генерации с исходной диагностикой провайдера.

Существующий лимит попыток сохраняется. Если все попытки завершились provider
error, наружу выходит последняя provider-ошибка, а не `JSONDecodeError`. Ответы
без error tag по-прежнему проходят существующий JSON extraction и проверку
числа/идентичности вопросов.

## Компоненты и поток данных

1. Администратор выбирает role-алиас или вводит прямой ID.
2. Settings endpoint валидирует значение и атомарно сохраняет его.
3. Ручная или плановая генерация читает один `daily_trivia_llm_model`.
4. Общая нормализация преобразует alias либо сохраняет прямой ID.
5. Router сначала вызывает preferred model, затем известную fallback-цепочку.
6. Daily Trivia либо разбирает успешный JSON, либо сообщает исходный provider
   error.

## TDD и проверка

До production-кода добавляются тесты, которые должны упасть по ожидаемой
причине:

1. Оба legacy-алиаса преобразуются в правильные role-модели; будущий прямой ID
   остаётся неизменным.
2. Для custom preferred model обе fallback-функции возвращают полный известный
   порядок, даже если `AVAILABLE_MODELS` скрывает часть цепочки.
3. Для preferred model внутри цепочки fallback начинается со следующей модели.
4. Settings endpoint принимает alias, валидирует прямой model ID, не изменяет
   настройку при `unsupported`/`unavailable` и возвращает различимые статусы.
5. Админский интерфейс позволяет ввести произвольный ID и показывает aliases как
   подсказки.
6. Ручная и автоматическая генерация читают одно сохранённое значение.
7. Tagged provider error с `404 NOT_FOUND` не передаётся в JSON parser и
   сохраняется в итоговой диагностике.
8. Валидный JSON по-прежнему создаёт требуемое число идентифицированных
   вопросов.
9. Целевые config/router/web/trivia тесты, затем связанный набор тестов и
   `scripts/check_encoding.py` проходят без регрессий.

## Вне области изменений

- автоматическое добавление прямого override в глобальный `/models`;
- изменение API-ключей, квот или алгоритма их ротации;
- поддержка OpenRouter, Opencode или FreeTheAI в этой конкретной настройке;
- изменение промптов, структуры вопросов или логики проверки дубликатов.
