# Замена Portainer Logs — Implementation Plan

> **For agentic workers:** использовать `executing-plans` после согласования решения; выполнять задачи последовательно. Делегирование, commit, push и deploy требуют отдельного запроса пользователя.

**Goal:** дать оператору приватный веб-интерфейс поиска структурированных логов с ограниченной загрузкой в браузер и историей между деплоями.

**Architecture:** приложение продолжает писать NDJSON в Docker `local`; Grafana Alloy читает выбранные контейнеры через Docker API и отправляет записи в Loki; Grafana предоставляет поиск и сохранённые представления. Стек наблюдаемости разворачивается независимо от приложения и не становится условием его запуска.

**Tech Stack:** Docker Compose, Grafana, Loki single-binary с TSDB/filesystem, Alloy, ограничивающий Docker API proxy.

**Spec:** проект решения в разделе ниже. Утверждён для немедленной реализации 2026-09-11. План подготовлен по checkout `fd63c808`; VPS и падающая вкладка не исследовались.

## Проект решения и ограничения

### Что установлено

- `app/observability/config.py` задаёт стандартный потолок события 32768 байт; `app/observability/pipeline.py` применяет бюджет. В runtime он может быть переопределён.
- `docs/logging.md` описывает schema-v1, корреляцию, scrubbed content до 2048 символов, очередь с байтовым ограничением и режим `full` по умолчанию.
- `.github/workflows/deploy.yml` запускает production через `docker run`: основной контейнер `tg-bot`, миграции `tg-migrate`, вспомогательные процессы. Используется `local`, `max-size=20m`, `max-file=5`.
- Корневой `docker-compose.yml` — local legacy, не источник production deployment.
- В текущем checkout нет отдельного коллектора и поискового хранилища логов. Реальное состояние VPS из этого не следует.

100 записей по 32 КиБ — примерно 3,125 МиБ исходного текста, 1500 — 46,875 МиБ. DOM, разбор JSON и буферы могут увеличить расход памяти, но этих расчётов недостаточно для установления причины OOM. Версия Portainer, размер ответа, фактический tail и память вкладки неизвестны. План не обещает исправление конкретного бага Portainer.

### Варианты

| Вариант | Применимость | Компромисс |
| --- | --- | --- |
| **Grafana + Loki + Alloy — рекомендуется** | Поиск по времени, полям, request/trace, история независимо от жизни контейнера | Несколько сервисов; нужны ресурсные лимиты и обслуживание хранения |
| Dozzle self-hosted | Быстрая специализированная замена Logs; JSON, фильтры, SQL-поиск | Долговечность истории и поведение больших выборок нужно проверять отдельно; сам просмотрщик не заменяет политику хранения |
| Управляемый сервис логов | Разгрузка VPS и меньше обслуживания | Внешняя передача пользовательских сообщений, стоимость и новая граница доверия; только с отдельным одобрением |

Рекомендуется self-hosted, без отправки сообщений стороннему SaaS. Если на текущем VPS нет запаса памяти/диска, не устанавливать стек туда автоматически: выбрать отдельный приватный узел или согласовать облегчённый вариант.

### Контракт MVP

- Заменяем просмотр/поиск Logs, не контейнерное управление Portainer. Portainer не удаляется, доступ к shell/start/stop в новом интерфейсе не добавляется.
- Приложение, schema-v1, `LOG_CONTENT_MODE=full`, редактирование чувствительных данных, очередь и Docker rotation сохраняются. Смена формата на text, отключение полезных событий и увеличение лимитов не входят в решение.
- Первая версия собирает только основной бот. Короткоживущие `--rm`-контейнеры миграций/проверок не объявляются покрытыми: discovery может не успеть их обнаружить. Их надёжный сбор — отдельное расширение.
- Labels Loki: `service_name`, `environment`, `level`. `request_id`, `trace_id`, `event_id`, actor IDs, `release`, `instance_id`, `key_suffix` остаются JSON-полями, не labels. Это ограничивает число потоков.
- Исходный NDJSON сохраняется; разобранный `timestamp` используется как время события. Невалидные/неизвестные события не отбрасываются молча: отдельный ограниченный поток `parse_status=invalid`, Docker timestamp и счётчик ошибок.
- Стартовый retention — 7 суток, включая full content; это предлагаемая политика для согласования. Удаление асинхронное, не обещать физическое стирание ровно в момент 168 часов.
- Первый доступ: Grafana на `127.0.0.1:3000`, SSH tunnel и отдельная учётная запись Grafana. Anonymous/sign-up выключены. Не переиспользовать `ADMIN_SECRET` бота.
- Loki, Alloy и Docker proxy без опубликованных host-портов, в выделенных сетях. Loki `auth_enabled` не считать пользовательской аутентификацией. При переносе между хостами обязателен защищённый транспорт с аутентификацией.
- Docker socket недоступен Grafana/Loki. Alloy получает только ограниченный API через proxy. Mount socket с `:ro` сам по себе не запрещает управляющие Docker API запросы.
- Основной экран: последние 15 минут, максимум 100 событий, короткое представление, полный JSON по раскрытию. Auto-refresh и live tail по умолчанию выключены; серверный максимум выдачи — 500 событий, timeout запроса — 10 секунд. История запрашивается временными окнами, без автоматической бесконечной подгрузки.
- Скрытие полей в таблице не является контролем доступа: допущенный к datasource оператор может прочитать весь защищённый поток. Экспорты тоже чувствительны.
- Исходная Docker-история — ограниченное окно восстановления, не архив. Persistent positions/WAL уменьшают потери, но не дают exactly-once; дубликаты проверять по `event_id`. Удалённые до сбора данные невосстановимы.

## Задача 1. Снять безопасный baseline и подтвердить ёмкость

**Файл результата:** создать `docs/operations/log-viewer-baseline.md` только с агрегатами, без сообщений, DSN, env и unrestricted inspect.

- [ ] Уточнить версию Portainer/браузера, где показан OOM; отдельно проверить, не завершался ли процесс Portainer или бот. По решению владельца это наблюдение не блокирует немедленный переход.
- [ ] В согласованном диагностическом доступе собрать на VPS `free -m`, `df -h`, `docker stats --no-stream` и только выбранные поля состояния/LogConfig через `docker inspect --format`. Не запускать миграции.
- [ ] Из ограниченного локального окна NDJSON вычислить число событий/секунду и p50/p95/max байтов строки без вывода содержимого. Из браузера записать только агрегатный размер ответа и память процесса, не сохранять HAR с сообщениями/сессионными данными в репозиторий.
- [ ] Рассчитать сутки хранения: средние байты/с × 86400; затем измерить фактический рост Loki на синтетическом стенде. Учесть TSDB, WAL, compactor, Alloy и запас, не предполагать фиксированное сжатие.
- [ ] Начальный бюджет испытания: Loki 1024 МиБ, Grafana 512 МиБ, Alloy 256 МиБ, proxy 64 МиБ; это гипотеза для проверки, не заявленные минимальные требования. Нужен запас ОС и пиков бота сверх этой суммы. При нехватке ресурсов размещение требует решения владельца.
- [ ] Отвести отдельный ограниченный filesystem/quota под данные логов; retention не защищает от всплеска записи и заполнения диска. Предусмотреть предупреждения на 70/85% и остановку приёма до угрозы диску приложения.

**Приёмка:** агрегаты получены либо явно отмечены как недоступные. По явному решению владельца от 2026-09-11 неизвестные live-показатели не вводят календарную задержку: deploy использует консервативные лимиты и останавливается в том же запуске, если сервисы не стартуют.

## Решения перед production

Утвердить self-hosted стек, хост с измеренным запасом ресурсов и 7 суток хранения full-content логов. Первый доступ через SSH tunnel не требует нового публичного домена. Публичный HTTPS/SSO, SaaS, увеличение retention и полный отказ от Portainer — отдельные решения, не неявные пункты MVP.

Переход выполняется одним успешным CI/deployment run без суточных или недельных ожиданий. Нагрузочные проверки используют синтетический объём и сокращённые стендовые интервалы.
