# Redis VPS migration implementation plan

Approved scope: fix the Redis audit findings, migrate existing data to an isolated
VPS Redis, configure local backups and monitoring, verify and publish to
`vps_testai`. This is an execution record, not runtime authority.

## Design and constraints

- Preserve all existing data, absolute expirations and queue ownership. Pause the
  sole bot writer during the final copy; verify source/destination before switching.
- Own only the `gemaibot-redis` Compose project, network, named volume and
  `/opt/gemaibot-redis` directory. Never recreate another project's infrastructure.
- Redis 8.8 patch release pinned by digest; 256 MiB maxmemory/noeviction, 768 MiB
  container limit, AOF every second, private network and separate app/admin ACLs.
- Deployment reads the VPS-owned bot environment file; pushes preserve Redis,
  credentials, volume and backups. An uncompleted migration blocks deployment.
- User chose local backups: 24 hourly + 7 daily recovery points, 2 GiB total cap;
  preserve the latest valid copy, alert on errors/oversize. No off-host durability claim.
- Disable transparent retries of uncertain mutations; retain explicit safe retries.
- Never print credentials, queue payloads, key names containing user data or dumps.

## Execution

- [x] Regression-first fixes: cached queue scripts, bounded idle polling, atomic
  game quotas, bounded game caches, explicit Redis retries and separate readiness.
- [x] Infrastructure: idempotent Compose installer, backup/retention/restore probe,
  bounded monitoring, deployment integration and operator documentation.
- [x] Verify scripts on an isolated Redis/container; test wrong namespace, occupied
  resource names, incomplete migration, missing backup, restore and uncertain writes.
- [x] Establish baseline for neighboring containers; provision empty isolated Redis.
- [x] Stop bot, copy/verify data and TTLs, retain protected rollback snapshot, switch
  existing bot and verify readiness. No automatic return to the old Redis after writes.
- [ ] Run local gates and real Redis contracts, review changes, commit/push.
- [ ] Verify CI/autodeploy, Redis identity/data survival, backup restore, monitoring,
  bot health/Telegram connectivity and unchanged neighboring infrastructure.

## Review focus

Loss of a Redis response must not repeat a claim or open another quota budget.
Idle polling must still discover remote/delayed work and lease expiry within 5 s.
Backup retention must not delete unrelated files or the last valid backup.
Deployment/reboot must preserve Redis identity and credentials without public ports.
Migration must preserve binary values, hashes/sets and absolute TTLs, fail closed on
verification errors, and leave the old writer stopped after the destination is active.
