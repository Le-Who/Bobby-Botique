## Атомарное сохранение беседы

Раньше [репозиторий](../app/repos/conversations.py) отдельно создавал запись беседы,
затем вызывал процедуру сохранения истории. Ошибка процедуры логировалась, но
возвращался успешный ID. Команда `/save` сообщала об успехе и увеличивала метрику,
хотя история не была сохранена. Один существующий тест прямо ожидал такой результат.

Теперь обе записи используют одно соединение и одну транзакцию. Ошибка процедуры
выходит из транзакции в существующий failure-path, отмена распространяется вызывающему
коду, а ID возвращается после успешного выхода из транзакции. Независимые повторы
pooled query helper не применяются к отдельным записям этой транзакции.

[Новые тесты](../tests/test_conversation_save_atomicity.py) сохраняют реальные
repository, query helper и command handler; драйвер БД, чтение chat-state и внешние
эффекты команды синтетические. Проверяются ошибки insert/procedure/transaction exit, отмена во время
процедуры и ожидания commit, пустая и непустая история, точные owner/metadata,
сохранность прежних строк и освобождение соединения. До завершения transaction exit
команда не сообщает успех и не увеличивает метрику. Исправлен
[старый тест](../tests/test_save_conversation.py), ожидавший ID при ошибке процедуры.

Отдельный сценарий моделирует потерю подтверждения уже выполненного commit: строки
остаются записанными, операция не повторяется автоматически, успех не объявляется.
Синтетические rollback-сценарии не доказывают откат после неоднозначного реального
COMMIT ACK. SQL процедуры, RLS и согласованный snapshot при конкурентном изменении
чата требуют отдельных проверок PostgreSQL.

## Приём запроса после сетевой отмены

В [обработчике сообщений](../app/handlers/messages.py) повторная проверка после
отмены зависшего запроса учитывала только lock. Старый worker мог уже освободить
lock, продолжая завершать long-wait notice; его busy-резервация оставалась активной.
Новый запрос всё же создавал placeholder и запускал downstream-обработку.

Повторная проверка теперь учитывает и `UserState.is_processing`, и canonical lock.
Это также защищает резервацию нового владельца, если два повтора одновременно
прошли к проверке, а первый уже принят и ожидает direct-intent preparation.
Существующие порог 15 секунд и пауза повторной проверки 150 мс сохранены.

[16 новых случаев](../tests/test_message_network_stall_admission.py) используют
реальные handler, state, debounce, TaskManager и heartbeat retirement. События
удерживают нужные границы вместо ожидания случайного расписания. Проверяются
быстрое и затянувшееся завершение, комбинации text/photo, освобождённый lock при
живой notice, повторные попытки, другой пользователь, отмена самого повтора,
конкурирующие повторы и здоровые запросы до/на пороге либо после возобновления stream.
RED доказывает преждевременный admission и пересечение работы; произвольная порча
состояния этим воспроизведением не установлена.

## Устойчивость проверки CI-выборки

Первый полный прогон остановился после **704 passing cases**: существующий тест
дважды собирал весь корпус приложения через subprocess в пределах общего
25-секундного бюджета. Первый subprocess превысил лимит. Отдельное воспроизведение
тоже завершилось таймаутом; похожее давление на deadline отмечалось ранее.

[Исправленная проверка](../tests/test_ci_workflow_config.py) копирует настоящий
`pytest.ini` во временный проект и один раз исполняет точные pytest-аргументы из
workflow. Четыре ожидаемых nodeid заданы литералами: module/class/function markers,
вложенный неизвестный модуль и параметризация. Обычные и integration controls
проверяют исключение лишних тестов. Мутация fixed-file selector выявила три пропуска,
удаление `-m browser` — три лишних случая. Неудачные внешние mutation wrappers
с ошибками обхода Windows Temp исключены из доказательства этих мутаций.

Unit-проверка устанавливает поведение selector на контролируемом корпусе. Настоящий
required browser job по-прежнему собирает и запускает тесты репозитория и завершится
ошибкой при пустой выборке. Workflow, 25-секундный subprocess timeout и 30-секундный
test timeout не изменялись.
