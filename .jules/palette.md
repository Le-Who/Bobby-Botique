## 2024-05-18 - Missing ARIA States on Custom Navigation Tabs
**Learning:** Found a recurring pattern where custom-built tab navigations (like the one in `dashboard.html`) only toggle visual states (e.g., CSS `.active` classes) without signaling state changes to screen readers via `aria-selected` and `aria-controls` properties, preventing users from tracking active tabs correctly.
**Action:** When building custom tab components or enhancing existing ones, ensure the parent element has `role="tablist"`, each child button has `role="tab"`, and Javascript click handlers toggle `aria-selected` attributes identically to the visual classes. Add `role="tabpanel"` to the corresponding panel elements.
## 2024-04-06 - Missing Connective ARIA Attributes in Dynamic UI Elements
**Learning:** Dynamic UI components (such as custom tabs and live-updating badges) in this application frequently omit essential WAI-ARIA connective attributes like `aria-labelledby`, `aria-live`, and explicit `id` bindings. This pattern degrades screen reader comprehension because active panels are orphaned from their tabs and dynamic error updates are missed.
**Action:** Always verify and implement complete ARIA patterns (specifically `role="tablist"`, `role="tab"`, `role="tabpanel"`, and `aria-labelledby` linkages) for custom components, and use `aria-live` for badges or counters that update dynamically without page reloads.
