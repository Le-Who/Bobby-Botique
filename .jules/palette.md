## 2024-05-18 - Missing ARIA States on Custom Navigation Tabs
**Learning:** Found a recurring pattern where custom-built tab navigations (like the one in `dashboard.html`) only toggle visual states (e.g., CSS `.active` classes) without signaling state changes to screen readers via `aria-selected` and `aria-controls` properties, preventing users from tracking active tabs correctly.
**Action:** When building custom tab components or enhancing existing ones, ensure the parent element has `role="tablist"`, each child button has `role="tab"`, and Javascript click handlers toggle `aria-selected` attributes identically to the visual classes. Add `role="tabpanel"` to the corresponding panel elements.
## 2025-04-14 - Full ARIA Patterns for Dynamic UI Components
**Learning:** Dynamic tab interfaces require a comprehensive WAI-ARIA pattern. It's not enough to just use `role="tablist"` and `role="tab"`. The `role="tabpanel"` containers must explicitly link back to their respective tab buttons using `aria-labelledby="[tab-id]"`, and the tab buttons need `id` attributes to complete the connection. Similarly, dynamic UI counters (like error badges that toggle visibility or update values) need `aria-live="polite"` to ensure screen readers announce their changes, and form validation error messages require `role="alert"` to be immediately surfaced to assistive tech.
**Action:** Always complete the full bidirectional ARIA link (`id` to `aria-labelledby`) when implementing or modifying tab components, use `role="alert"` for validation errors, and apply `aria-live` to dynamically updating status badges.
