## 2024-05-18 - Missing ARIA States on Custom Navigation Tabs
**Learning:** Found a recurring pattern where custom-built tab navigations (like the one in `dashboard.html`) only toggle visual states (e.g., CSS `.active` classes) without signaling state changes to screen readers via `aria-selected` and `aria-controls` properties, preventing users from tracking active tabs correctly.
**Action:** When building custom tab components or enhancing existing ones, ensure the parent element has `role="tablist"`, each child button has `role="tab"`, and Javascript click handlers toggle `aria-selected` attributes identically to the visual classes. Add `role="tabpanel"` to the corresponding panel elements.

## 2025-02-12 - Missing Strict ARIA References on Tab Panels and Badges
**Learning:** Found that custom tab components (in `dashboard.html`) lacked strict mapping between the tab elements and their corresponding panels. Relying on visual structure is insufficient for screen readers; the panels must explicitly reference the tabs that control them. Also discovered that dynamic elements like hidden counters (e.g. error badges) require explicit ARIA attributes to correctly notify users when they become visible and update.
**Action:** Always ensure that each tab button has an `id` that strictly maps to the `aria-labelledby` attribute of its corresponding `tabpanel`. When building or enhancing dynamic badging elements (like hidden-by-default error counters), ensure they have both `aria-live="polite"` and `aria-atomic="true"` attributes so screen readers announce dynamic changes correctly.
