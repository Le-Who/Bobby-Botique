## 2024-05-18 - Missing ARIA States on Custom Navigation Tabs
**Learning:** Found a recurring pattern where custom-built tab navigations (like the one in `dashboard.html`) only toggle visual states (e.g., CSS `.active` classes) without signaling state changes to screen readers via `aria-selected` and `aria-controls` properties, preventing users from tracking active tabs correctly.
**Action:** When building custom tab components or enhancing existing ones, ensure the parent element has `role="tablist"`, each child button has `role="tab"`, and Javascript click handlers toggle `aria-selected` attributes identically to the visual classes. Add `role="tabpanel"` to the corresponding panel elements.
## 2026-03-05 - Missing ARIA attributes in dynamic UI components
**Learning:** Dynamic UI components (such as form validation error messages, tab patterns, and numeric badges) frequently omit connective ARIA attributes in this codebase, hindering proper announcement and relationships for screen readers. Elements generated conditionally or updated via JS (like `<div class="error-msg">` or `<span class="tab-badge">`) were missing `role="alert"`, `aria-live`, and explicit ID linking (`aria-controls`, `aria-labelledby`).
**Action:** When working on dynamic or JS-driven UI updates, explicitly verify that WAI-ARIA connective attributes are complete. Forms need `role="alert"` on error banners, dynamic counters need `aria-live="polite"`, and tab panels must explicitly declare `id`s and `aria-labelledby`.
