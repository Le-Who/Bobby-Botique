## 2024-05-18 - Missing ARIA States on Custom Navigation Tabs
**Learning:** Found a recurring pattern where custom-built tab navigations (like the one in `dashboard.html`) only toggle visual states (e.g., CSS `.active` classes) without signaling state changes to screen readers via `aria-selected` and `aria-controls` properties, preventing users from tracking active tabs correctly.
**Action:** When building custom tab components or enhancing existing ones, ensure the parent element has `role="tablist"`, each child button has `role="tab"`, and Javascript click handlers toggle `aria-selected` attributes identically to the visual classes. Add `role="tabpanel"` to the corresponding panel elements.

## 2024-04-20 - Ensure Full WAI-ARIA Connectivity on Dynamic Dashboard Elements
**Learning:** For dynamic components like custom tabs and status badges, simply having `role="tab"` or basic state changes is insufficient for screen readers. Tabs require `id` attributes that strictly link to their corresponding panels via `aria-labelledby`. Dynamic components (e.g., error counters that are hidden and updated via JS) require `aria-live="polite"` and `aria-atomic="true"` to announce state changes effectively without interrupting the user.
**Action:** Always verify that custom JS tab architectures explicitly bind `<button id="X">` to `<div aria-labelledby="X">`, and add `aria-live` attributes to any dynamically updated counter or badge.
