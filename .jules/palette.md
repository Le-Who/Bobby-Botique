## 2024-05-18 - Missing ARIA States on Custom Navigation Tabs
**Learning:** Found a recurring pattern where custom-built tab navigations (like the one in `dashboard.html`) only toggle visual states (e.g., CSS `.active` classes) without signaling state changes to screen readers via `aria-selected` and `aria-controls` properties, preventing users from tracking active tabs correctly.
**Action:** When building custom tab components or enhancing existing ones, ensure the parent element has `role="tablist"`, each child button has `role="tab"`, and Javascript click handlers toggle `aria-selected` attributes identically to the visual classes. Add `role="tabpanel"` to the corresponding panel elements.
## 2025-04-27 - Strict WAI-ARIA tab mapping and dynamic badge attributes
**Learning:** Custom tab components in this codebase (like those in dashboard.html) often lack complete WAI-ARIA patterns. When building or enhancing dynamic badging elements (like hidden-by-default error counters), ensure they have both `aria-live="polite"` and `aria-atomic="true"` attributes so screen readers announce dynamic changes correctly. Ensure each tab button has an explicit `id` attribute that strictly maps to the `aria-labelledby` attribute of its corresponding `tabpanel`.
**Action:** When adding or modifying custom tab bars or dynamic badges, ensure to include corresponding WAI-ARIA attributes (`id` on button with `aria-labelledby` on tabpanel, and `aria-live="polite"` with `aria-atomic="true"` on dynamic badges) for screen reader accessibility.
