## 2024-05-18 - Missing ARIA States on Custom Navigation Tabs
**Learning:** Found a recurring pattern where custom-built tab navigations (like the one in `dashboard.html`) only toggle visual states (e.g., CSS `.active` classes) without signaling state changes to screen readers via `aria-selected` and `aria-controls` properties, preventing users from tracking active tabs correctly.
**Action:** When building custom tab components or enhancing existing ones, ensure the parent element has `role="tablist"`, each child button has `role="tab"`, and Javascript click handlers toggle `aria-selected` attributes identically to the visual classes. Add `role="tabpanel"` to the corresponding panel elements.
## 2026-04-05 - Missing ARIA Labels on Dashboard and Login Error Messages
**Learning:** The application's dashboard `app/templates/dashboard.html` lacked proper `aria-labelledby` linkages on tab panels, `id` definitions on tab buttons, and `aria-label` definitions on the `tablist` container. Furthermore, dynamic UI elements like `error-badge` did not leverage `aria-live="polite"`. In `app/templates/login.html`, standard form validation messages didn't use `role="alert"`, rendering them invisible to screen reader announcements.
**Action:** Consistently apply `role="alert"` to form error messages (`.error-msg`). Ensure complete ARIA patterns are provided to complex component structures like tabs, requiring linking IDs to the panels via `aria-labelledby`, explicitly naming the `tablist` element with `aria-label`, and providing `aria-live` regions for asynchronous or dynamic update badges.
