## 2024-05-18 - Missing ARIA States on Custom Navigation Tabs
**Learning:** Found a recurring pattern where custom-built tab navigations (like the one in `dashboard.html`) only toggle visual states (e.g., CSS `.active` classes) without signaling state changes to screen readers via `aria-selected` and `aria-controls` properties, preventing users from tracking active tabs correctly.
**Action:** When building custom tab components or enhancing existing ones, ensure the parent element has `role="tablist"`, each child button has `role="tab"`, and Javascript click handlers toggle `aria-selected` attributes identically to the visual classes. Add `role="tabpanel"` to the corresponding panel elements.

## 2024-05-18 - Missing ARIA States on Custom Navigation Tabs
**Learning:** Custom-built tab navigations utilizing `div` elements and `onclick` events inherently lack semantic meaning and keyboard support, making them completely inaccessible to screen reader users and those navigating without a mouse.
**Action:** When building custom tab components, ensure the parent container has `role="tablist"`, each child button has `role="tab"` with `aria-controls` pointing to its panel, and the panel has `role="tabpanel"` with `aria-labelledby` pointing to its tab. Furthermore, if the tab is not a native `<button>`, ensure keyboard accessibility by adding `tabindex="0"` and an `onkeydown` handler to process 'Enter' and 'Space' key events, strictly including `event.preventDefault()` to prevent default page scrolling on Space. Javascript click handlers must toggle `aria-selected` attributes identically to the visual classes.
